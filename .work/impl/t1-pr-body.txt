## Problems and decisions in this PR

- The eleventh and twelfth rounds are not in the local `.work/DECISIONS.md`; they are read from `origin/wip/handoff`.
- The carried code does not compile before the adapt commit, so 4a (0cb43b7) comes before the strict-flag commit 3 (166a375), as the task allows.
- `InputPort` is `private[tui4s]` in `tui4s.internal`, not public in `tui4s.spi` as in PR 5: its element is now the crossterm `Event` (D-21 a), and RC-36 forbids a jatatui type in a public signature. A facade that needs scripted input uses the internal seam (it is inside `tui4s`).
- `HeadlessControl` is not carried: no run uses it (the runner's Canvas resizes a TestBackend; the tests use `RecordingControl`).
- `TuiError` has no `AppFailed`: a failure of the UI construction comes out of `Tui.run` as it is (a panic), after the restore; a handler that fails is logged and the run goes on (C3). A failed write to the terminal (an `IOException` of the backend) and a failed read (the input thread) are `TerminalIO`.
- The non-BMP rule (twelfth round) cannot be met for TYPED keys: a probe in a pseudo-terminal (`Probe.java` on the crossterm jar) shows that the JNI layer of jatatui 0.31.0 gives `KeyCode.Char` the low 16 bits of the character (a typed U+1F600 arrives as U+F600, a private-use character; `KeyCode.Char` holds one Java `char`). The mapping cannot see the difference, so such a key arrives as a wrong character. A bracketed paste is right (`Paste[string=x😀y]`, code points 78, 1f600, 79), and `TextEdit` inserts it as it is. EventMapping drops half of a surrogate pair. Documented in the EventMapping Scaladoc, AGENTS.md and examples/README.md.
- With a `KyoApp` main, `kill -TERM` gives exit 143 and `kill -INT` 130, with the terminal restored (seen once with a script in a pseudo-terminal): Kyo's signal handling interrupts the run, and the bracket restores the terminal. D-24 puts 130 and 143 in T2 (`TuiApp`); T2 can build on this.
- The `JAVA_HOME` of this container is JDK 21 (`java` on `PATH` is 25). The first PTY try failed with "Unrecognized option: --sun-misc-unsafe-memory-access=allow". run.sh now checks that the java of the start scripts is 25 or later and says so; the local runs set `JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64`. CI uses setup-java 25.
- The runner sends only the cells that change, so "Count: 0" comes as "Count:", a cursor move and "0": the kit waits for "Count:" (the second try waited for "Count: 0" and timed out).
- Without `--enable-native-access` (and without `deny`), JDK 25 prints its four-line warning into the terminal BEFORE the alternate screen (seen in a pseudo-terminal); it stays above the prompt after the run. The build comment and the docs say so (PR 5 said "over the UI").
