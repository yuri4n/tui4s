The C3 PR body P-12 says these Evt forms are "deferred (D-30)". That was a stretch: D-30 defers MOUSE input and TERMINAL focus events, not the DOM-shaped handler overloads, which a kyo-ui app can register and which then silently never run. Round 2 corrects P-12 and the AGENTS.md sentence "as kyo-ui does", with a short "where tui4s follows the Click rule for a key" paragraph.

## The change (one commit per finding, each with its test and a negative control; P-9: new commits only)

1. `Dispatch.activate` (new, replaces the target-only `click`): for a Button or Anchor target, walk `ch` innermost first: on the target run `onClickSelf`, `onClickSelfEvt(mouse)`; on every element (target first) run `onClickEvt(mouse)` then `onClick`; when the element is a Form and the target is a Button, run `onSubmit` then `onSubmitEvt(mouse)` (an Anchor does not submit; kyo-ui: "Only Button clicks submit forms"); stop after an element where a click handler was declared (self forms count only on the target) and `stopPropagation` is set (kyo-ui's `keepBubbling(elem, declared)`); a disabled target runs no self handler and no click handler of its own but the ancestors still run (kyo-ui line 511-512: "Disabled or hidden elements ignore their own click handler, but allow bubbling"; today tui4s skips a disabled target entirely in `defaults`: keep that, it is the C3 rule R2-3 territory; say so). For the Button activation inside a form, `defaults` must NOT also run its keydown `submit` (one submit per key). Tests (DispatchTest): a button inside a div with `onClick`: Enter runs the button's then the div's `onClick` (order innermost first); with `stopPropagation(true)` on the button only the button's runs; the self forms run on the target only; an anchor inside a form does not submit, a button does, once, with both forms; the 500-key glitch leaf and AppsTest still pass (the Counter buttons have no clickable ancestors).
2. Every submit runs both forms: the keydown `submit` of `defaults` (Enter on a text input inside a form) runs `onSubmit` then `onSubmitEvt(mouse)`. Test: a form with both forms registered and a text input: Enter runs both, once each, in that order; PasteTest's "never a submit" leaf still holds.
3. `setFocus` runs both forms for blur and focus. Test (DispatchTest, the existing onFocus/onBlur leaf extended): Tab from A to B runs A's `onBlur`, `onBlurEvt`, then B's `onFocus`, `onFocusEvt`, each once, in that order; an automatic focus move (runHandlers = false) runs none (C3 P-12 stays true).
