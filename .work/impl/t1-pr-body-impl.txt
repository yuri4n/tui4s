After the merge, a kyo-ui app runs in a real terminal: `tui4s.Tui.run(options)(ui)` and `tui4s.Tui.run(ui)` put the terminal in raw mode, enter the alternate screen, start an input thread that maps the crossterm events to kyo-ui keys, pastes and resizes, run the C2/C3 runner on a crossterm backend, and restore the terminal in every way that a run ends (a quit, a failure, an interrupt, the JVM shutdown hook). `ui` gets the quit value (as in `Headless.start`); `Tui.quit` and Ctrl-C end the run too. A run that cannot start fails with a Kyo-free `tui4s.TuiError` before the terminal changes. The Counter example runs from a start script (`sbt examples/launchers`, then `examples/target/bin/counter`), and a PTY kit checks it in a pseudo-terminal, locally and in the new CI job `terminal`. The three bot findings of the old PRs 4 and 5 are fixed, each in its own commit with a regression test and a negative control. Base: PR #13 (C3, `feat/kyoui-03-input`, f29b9ff).

The mapping cannot see the difference, so such a key arrives as a wrong character. A bracketed paste is right (`Paste[string=x😀y]`, code points 78, 1f600, 79), and `TextEdit` inserts it as it is. EventMapping drops half of a surrogate pair. Documented in the EventMapping Scaladoc, AGENTS.md and examples/README.md.
- With a `KyoApp` main, `kill -TERM` gives exit 143 and `kill -INT` 130, with the terminal restored (seen once with a script in a pseudo-terminal): Kyo's signal handling interrupts the run, and the bracket restores the terminal. D-24 puts 130 and 143 in T2 (`TuiApp`); T2 can build on this.
