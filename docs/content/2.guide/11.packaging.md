A `TuiApp` reads its command-line arguments with `args`, and gives its options with `options`. The Printing example sends the captured output to a log file:

<!-- from: examples/src/main/scala/examples/printing/Printing.scala#options -->
```scala [Printing.scala]
    def options(args: Chunk[String]): TuiOptions = args.toSeq match
        case Seq("--log", file, _*) =>
          TuiOptions(logFile = Some(Paths.get(file)))
        case _                      => TuiOptions()
```

Its main class has `override def options: TuiOptions = Printing.options(args)`.

## The JVM flags

The start scripts of the examples (sbt-native-packager) give these flags:

| Flag | Why |
| --- | --- |
| `--enable-native-access=ALL-UNNAMED` | The terminal library (crossterm) is native. Without the flag, JDK 25 prints a warning into the terminal before the UI starts. With `--illegal-native-access=deny`, the run fails with `TuiError.NativeAccessDenied`. |
| `--sun-misc-unsafe-memory-access=allow` | Kyo and Scala use `sun.misc.Unsafe`. |
| `-Xss16m` | Kyo's deep stacks. |
| `-Dkyo.scheduler.cycleIntervalNs=10000000` and three more scheduler values | Fewer split frames under load, and less CPU when the app is idle. |

A `TuiApp` sets the scheduler values in code before Kyo starts its scheduler. An app with a main of its own (a `KyoApp` that calls `Tui.run`) gives them as JVM flags. The ZIP does not hold a JDK: the machine needs JDK 25.

## Output while the UI runs

A print to stdout or stderr would write over the screen. So the run captures `System.out`, `System.err` and Scala's `println`, and prints the lines after it restores the terminal. With `logFile`, the lines go to that file.

## Exit codes and signals

| How the run ends | Exit code |
| --- | --- |
| `Tui.quit`, or the key Ctrl-C | 0 |
| A failure of the UI (printed after the restore) | 1 |
| `kill -TERM` | 143 |
| `kill -INT` | 130 |
| `kill -HUP` | 129 |

On a signal or a `System.exit`, a shutdown hook interrupts the run and waits at most 2 s for the restore of the terminal. In raw mode, the key Ctrl-C is a key, not a signal: `TuiOptions(ctrlCQuits = false)` gives it to the app.
