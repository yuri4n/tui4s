## One version for each module

Each module has its own version and its own releases:

| Module | Release tag |
| --- | --- |
| `tui4s-core` | `core-v<version>` |
| `tui4s-zio` | `zio-v<version>` |
| `tui4s-cats` | `cats-v<version>` |

A fix in `tui4s-zio` does not make a new `tui4s-core` or `tui4s-cats` release. The release notes of each tag are on the [GitHub releases page](https://github.com/yuri4n/tui4s/releases).

## Compatibility

tui4s uses [early semantic versioning](https://www.scala-lang.org/blog/2021/02/16/preventing-version-conflicts-with-versionscheme.html):

- `0.y.z` to `0.y.(z+1)`: binary compatible.
- `0.y` to `0.(y+1)`: can break binary compatibility.

Each published module declares `versionScheme := Some("early-semver")`, so sbt warns you about version conflicts.

`tui4s-zio` and `tui4s-cats` depend on `tui4s-core`. Each release of an integration depends on a released `tui4s-core`, never on a snapshot.
