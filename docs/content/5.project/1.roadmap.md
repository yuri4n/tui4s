No version of tui4s is published yet. The first release is `0.1.0-RC1` ([ADR 0014](/decisions/0014-release-per-module-tags-and-rc1)). Each line below is an open issue on GitHub. The issue has the details and the decision that it waits for. The [issue list](https://github.com/yuri4n/tui4s/issues) is the current state.

## Integrations

- A ZIO DSL module (`tui4s-zio`) over kyo-ui: [#18](https://github.com/yuri4n/tui4s/issues/18).
- A Cats Effect DSL module (`tui4s-cats`) over kyo-ui: [#19](https://github.com/yuri4n/tui4s/issues/19).
- The assistant: Codex app-server as a provider: [#48](https://github.com/yuri4n/tui4s/issues/48).

## Input

- Mouse input (click, wheel) as an opt-in: [#20](https://github.com/yuri4n/tui4s/issues/20).
- The kitty keyboard protocol, so that the terminal reports Shift-Enter: [#23](https://github.com/yuri4n/tui4s/issues/23).
- `inputFilter` and `inputMask` on text inputs: [#31](https://github.com/yuri4n/tui4s/issues/31).
- One-line inputs: `onChange` on each edit, not only on Enter: [#32](https://github.com/yuri4n/tui4s/issues/32).

## Rendering

- The terminal cursor shows under an overlay that does not trap the focus: [#30](https://github.com/yuri4n/tui4s/issues/30).
- Viewports: a stick-to-bottom mode: [#43](https://github.com/yuri4n/tui4s/issues/43).
- The painter: a wide glyph that the right edge of a clip cuts: [#44](https://github.com/yuri4n/tui4s/issues/44).
- The rendering cost: the scroll of a list is O(rows); `Toasts` and `Spinner` render on each tick: [#33](https://github.com/yuri4n/tui4s/issues/33).
- The runtime cost of tui4s (from the bench numbers): [#50](https://github.com/yuri4n/tui4s/issues/50).

## API

- A `ui"""..."""` template interpolator (intent only, [ADR 0017](/decisions/0017-deferred-templates-mouse-and-kitty)): [#21](https://github.com/yuri4n/tui4s/issues/21).
- `Tui.run`: the promise copy of the run result: [#46](https://github.com/yuri4n/tui4s/issues/46).

## Widgets and composables

- tui4s-widgets on the web: the unit scale, a click on `RadioGroup`, a list that follows: [#25](https://github.com/yuri4n/tui4s/issues/25).
- tui4s-use: `useProcess` holds a scheduler thread; a `LocalStorage` test; CRLF: [#45](https://github.com/yuri4n/tui4s/issues/45).
- More widgets: form validation, a file picker, a Markdown viewer, a calendar, a line chart: [#47](https://github.com/yuri4n/tui4s/issues/47).

## Web and kyo-ui

These issues are drafts for kyo-ui. The maintainer posts them upstream ([ADR 0019](/decisions/0019-upstream-kyo-issues-as-drafts)).

- The widgets on the web (as above): [#25](https://github.com/yuri4n/tui4s/issues/25).
- A keydown on a field in a nested region is lost (kyo-ui JS): [#26](https://github.com/yuri4n/tui4s/issues/26).
- A handled keydown cannot prevent the default (kyo-ui JS): [#27](https://github.com/yuri4n/tui4s/issues/27).
- Each Enter submits the form that holds the field (kyo-ui JS): [#28](https://github.com/yuri4n/tui4s/issues/28).
- A `Stylesheet` cannot override inline styles (kyo-ui): [#29](https://github.com/yuri4n/tui4s/issues/29).
- Bound inputs lose keys that come fast (kyo-ui JS): [#37](https://github.com/yuri4n/tui4s/issues/37).
- A bound value goes into the DOM `value` attribute (kyo-ui JS): [#38](https://github.com/yuri4n/tui4s/issues/38).
- A cell or `ch` length unit (kyo-ui): [#39](https://github.com/yuri4n/tui4s/issues/39).

## Kyo and jatatui

- Remove the own signal watcher of the runner when Kyo fixes the `Signal.observe` leak: [#8](https://github.com/yuri4n/tui4s/issues/8).
- Measure the split frames again when Kyo closes the lost wakeup of `observe`: [#9](https://github.com/yuri4n/tui4s/issues/9).
- kyo-kernel 1.0.0-RC7 has JMH in compile scope: [#40](https://github.com/yuri4n/tui4s/issues/40).
- A runner outside the package `kyo` cannot honour `UI.scrollIntoView`: [#41](https://github.com/yuri4n/tui4s/issues/41).
- jatatui: `NativeLoader` leaves one `/tmp/jni-*` directory per start: [#42](https://github.com/yuri4n/tui4s/issues/42).

## Platforms

## Propose a feature

Open an [issue on GitHub](https://github.com/yuri4n/tui4s/issues/new/choose) with the feature request template. Give the use case, a small kyo-ui example of the UI, and what tui4s does today.
