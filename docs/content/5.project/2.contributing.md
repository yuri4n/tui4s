```sh
git clone --recurse-submodules https://github.com/yuri4n/tui4s
cd tui4s
nix develop                 # JDK 25, sbt, Node.js and the terminal test tools
sbt fmt                     # format the Scala and sbt files
sbt check                   # format, compile, lint, test, compatibility
examples/ptycheck/run.sh    # the real-terminal checklist in a pseudo-terminal
```

## The rules

- [CONTRIBUTING.md](https://github.com/yuri4n/tui4s/blob/main/CONTRIBUTING.md) tells how to send a change.
- [AGENTS.md](https://github.com/yuri4n/tui4s/blob/main/AGENTS.md) is the rule book, for humans and for agents: the toolchain, the commands, the rules for code, the purity rules and the release process.
- The [decision records](/decisions) give the reason for each rule.

## The checks

<!-- claude 2026-10-20: changed: the release rules row; created: the release notes row (ADR 0020; review fix: only the subsections under the first heading) -->

| Check | Command | What it checks |
| --- | --- | --- |
| The sbt checks | `sbt check` | The format, the compile with no warning in CI, the scalafix lint, all the tests, the binary compatibility. |
| The edge files | `bash scripts/edge-check.sh` | The headers of the edge files and the `scalafix:ok` comments. |
| The release rules | `bash scripts/version-order-test.sh` | The version form and order, the modules and the last tag of a module (`scripts/release-lib.sh`). |
| The release notes | `bash scripts/changelog-section-test.sh` | The extraction of the notes of a module from `CHANGELOG.md` (`scripts/changelog-section.sh`), and that each subsection `### tui4s-<module>` under the first heading of `CHANGELOG.md` has text. |
| The PTY kit | `examples/ptycheck/run.sh` | Each example in a real pseudo-terminal: the keys, the signals and the restore of the terminal. Run it after a change to the terminal code. |
| The Markdown regions | `MarkdownRegionsSuite` (in `sbt check`) | Each Scala block of `README.md` and of these pages is the text of a region of a source file. |
| The docs build | `pnpm install --frozen-lockfile && pnpm run build` in `docs` | The site builds with no network access. Set `NUXT_TELEMETRY_DISABLED=1`. |

Use JDK 25, and run one sbt process at a time in one checkout. Never start a terminal UI with `sbt run`: use the start scripts (`sbt examples/launchers`, then `examples/target/bin/<app>`).

## Releases

<!-- claude 2026-10-20: created: this section (ADR 0020) -->

The maintainer starts a release from the Actions form on `main` ([ADR 0020](/decisions/0020-release-from-the-actions-form)). The workflow checks everything before it creates a tag, waits for one approval, and then publishes each module to Maven Central in the order of the dependencies. A pull request that changes a published module adds a line under `## [Unreleased]` of `CHANGELOG.md`, in the subsection `### tui4s-<module>`: that text becomes the release notes.
